សេចក្តីណែនាំលម្អិតជាន់ខ្ពស់៖ ជំហានទី ២ - ការយល់ដឹងស៊ីជម្រៅអំពី Repository, Clone និង Git Workflow

នៅក្នុងមេរៀននេះ យើងនឹងស្វែងយល់យ៉ាងស៊ីជម្រៅអំពីរបៀបដំណើរការរបស់ Git នៅเบื้องក្រោយ (Under the hood) និងរបៀបប្រើប្រាស់ពាក្យបញ្ជាមូលដ្ឋានឱ្យបានត្រឹមត្រូវតាមស្ដង់ដារអ្នកជំនាញ។

---

### ១. ការស្វែងយល់ពីការបង្កើត Repository លើ GitHub ឱ្យបានស៊ីជម្រៅ
ពេលដែលអ្នកបង្កើត Repository ថ្មី វាមិនមែនគ្រាន់តែជា Folder ធម្មតានោះទេ ប៉ុន្តែវាមានជម្រើសសំខាន់ៗដែលអ្នកត្រូវយល់៖
- **Repository Name:** គួរតែប្រើសញ្ញា `-` ជំនួសឱ្យចន្លោះទទេ (Space) ឧទាហរណ៍៖ `my-awesome-project`។
- **Public vs Private:**
  - *Public:* នរណាក៏អាចមើលឃើញកូដរបស់អ្នកបានដែរ (ល្អសម្រាប់ Portfolio និង Open Source)។
  - *Private:* មានតែអ្នក ឬក្រុមការងារដែលអ្នកអនុញ្ញាតទេ ទើបអាចមើលឃើញ (ល្អសម្រាប់ Projects ផ្ទាល់ខ្លួន ឬការងារក្រុមហ៊ុន)។
- **Add a README file:** ឯកសារនេះជាទំព័រមុខនៃ Repo របស់អ្នក (សរសេរដោយ Markdown) ដែលពន្យល់ថាគម្រោងនេះធ្វើអ្វី និងរបៀបប្រើប្រាស់។
- **Add .gitignore:** ជម្រើសនេះសំខាន់ណាស់! វាប្រាប់ Git ឱ្យមិនបាច់តាមដាន (Ignore) ឯកសារដែលមិនចាំបាច់ ដូចជា ឯកសារ cache, ថត `node_modules` (សម្រាប់ Node.js), ឬ configuration ផ្ទាល់ខ្លួន។
- **Choose a license:** កំណត់សិទ្ធិផ្លូវច្បាប់របស់អ្នកដទៃក្នុងការយកកូដរបស់អ្នកទៅប្រើប្រាស់។

---

### ២. ការយល់ដឹងពីដំណើរការ Clone ថតកូដ (Git Clone Deep Dive)
ពេលដែលអ្នកវាយពាក្យ `git clone [URL]`៖
- Git មិនត្រឹមតែទាញយកឯកសារចុងក្រោយមកទេ ប៉ុន្តែវាទាញយក **ប្រវត្តិសាស្រ្តនៃការកែប្រែទាំងអស់ (Git History)** មកជាមួយផងដែរ។
- វាក៏បង្កើត Connection មួយហៅថា **`origin`** ដោយស្វ័យប្រវត្តិ ដែលភ្ជាប់កុំព្យូទ័ររបស់អ្នកទៅកាន់ GitHub Repository ដើម។

---

### ៣. ស្វែងយល់ពី "តំបន់ទាំង ៣" របស់ Git (The Three Trees / Areas of Git)
ដើម្បីយល់ច្បាស់ពី Git អ្នកត្រូវដឹងថាវារក្សាទុកកូដតាម ៣ កន្លែង៖
1. **Working Directory (ថតឯកសារក្នុងកុំព្យូទ័ររបស់អ្នក):** កន្លែងដែលអ្នកកំពុងសរសេរ និងកែប្រែកូដផ្ទាល់។
2. **Staging Area / Index (កន្លែងរៀបចំឯកសារ):** កន្លែងដែលប្រមូលផ្តុំឯកសារដែលអ្នកបានជ្រើសរើសរួចរាល់ ដើម្បីត្រៀមរក្សាទុក (Commit)។
3. **Local Repository (.git folder):** កន្លែងដែលប្រវត្តិសាស្រ្តនៃការ Commit ទាំងអស់ត្រូវបានរក្សាទុកអចិន្ត្រៃយ៍ក្នុងកុំព្យូទ័ររបស់អ្នក។

---

### ៤. វដ្តការងារស៊ីជម្រៅ (Advanced Git Workflow Step-by-Step)

#### ជំហានទី ១៖ ការពិនិត្យស្ថានភាពជាមួយ `git status`
ពាក្យបញ្ជា `git status` គឺជាភ្នែករបស់អ្នក វាបង្ហាញ៖
- **On branch main:** អ្នកស្ថិតនៅលើ Branch ណា។
- **Changes not staged for commit (ពណ៌ក្រហម):** ឯកសារដែលបានកែប្រែក្នុង Working Directory ប៉ុន្តែមិនទាន់បានដាក់ចូល Staging Area។
- **Changes to be committed (ពណ៌បៃតង):** ឯកសារដែលស្ថិតក្នុង Staging Area រួចរាល់សម្រាប់ Commit។
- **Untracked files:** ឯកសារថ្មីស្រឡាងដែល Git មិនទាន់តាមដាន។

#### ជំហានទី ២៖ ការប្រើប្រាស់ `git add` ឱ្យបានត្រឹមត្រូវ
- `git add .` : បញ្ចូលរាល់ឯកសារទាំងអស់ដែលបានកែប្រែ (ទាំងឯកសារថ្មី និងឯកសារកែប្រែចាស់) ចូលទៅក្នុង Staging Area។
- `git add filename.html` : ដាក់តែឯកសារជាក់លាក់ណាមួយប៉ុណ្ណោះ (ល្អប្រសិនបើអ្នកធ្វើការកែប្រែច្រើនកន្លែង តែចង់ Commit ដាច់ដោយឡែកពីគ្នា)។

#### ជំហានទី ៣៖ ការសរសេរ Commit Message តាមស្ដង់ដារ (Git Commit)
ការ Commit គឺដូចជាការថតរូបភាព (Snapshot) នៃកូដរបស់អ្នកនៅពេលនោះ។ ការសរសេរ Message គួរតែច្បាស់លាស់៖
- ប្រើប្រាស់ទម្រង់ស្ដង់ដារ (Conventional Commits):
  - `feat: add navigation bar` (ពេលបន្ថែមមុខងារថ្មី)
  - `fix: resolve login bug` (ពេលកែហ្វិចកំហុស)
  - `style: update css layout` (ពេលកែរចនាប័ទ្ម)
- ពាក្យបញ្ជា៖ `git commit -m "feat: add index.html structure"`

#### ជំហានទី ៤៖ ការបញ្ជូនកូដឡើងលើ (Git Push)
- ពេលវាយ `git push` (ឬ `git push origin main`) គឺបញ្ជូនរាល់ Commit ដែលមានក្នុង Local Repository របស់អ្នកឡើងទៅកាន់ Server របស់ GitHub ។
- ប្រសិនបើមានអ្នកផ្សេងបានកែប្រែ និង Push មុនអ្នក Git នឹងប្រាប់ថាមាន Conflict ដែលយើងនឹងរៀននៅជំហានបន្ទាប់។
